# График

## Зафиксированные архитектурные правила

- Общий UI/CSS является единым визуальным слоем.
- Не допускаются самовольные отдельные CSS-системы внутри отдельных веток.
- Если UI-компонент используется только одной веткой, это не означает, что его визуальная реализация должна дублироваться в этой ветке: общий UI-компонент остаётся общим, а принадлежность использования определяется веткой.
- Календарная сетка — один общий UI-компонент.
- Переключатель `Год → Месяц → День` — отдельный общий UI-компонент, используемый Графиком.
- Переключатель `Месяц → Год` — отдельный общий UI-компонент, используемый Журналом.
- Состояние и результат использования этих компонентов не являются общими: График и Журнал могут находиться на разных месяцах.
- Если в Графике календарная сетка или её состояние ошибочно связаны как единое состояние с другой веткой, это является ошибкой.
- Дополнительные настройки, относящиеся только к Графику, остаются принадлежностью Графика; их не следует превращать в глобальные настройки.

## UI

- Календарная сетка — общий UI.
- Управление рабочим периодом и формирование рабочего дня — ответственность Графика.
- Отображение рабочего дня в сетке — по состоянию, сформированному Графиком.
- Временной блок рабочего дня — специальное содержание Графика, использующее общий UI.
- Общие выпадающие/модальные элементы не дублируются внутри Графика.

## CSS

- Главный принцип: единый общий CSS.
- Специфические классы допустимы только как контекстные варианты общего визуального слоя, а не как отдельная визуальная система.


- `Профиль пользователя` — одна сущность.
- `Profile.js` — владелец сущности Профиль.
- Профиль управляет тремя группами данных: `Личные данные`, `Профессиональные данные`, `Рабочие данные`.
- Эти группы данных не являются тремя отдельными сущностями Профиля.
- `Настройки` не владеет сущностью Профиль.

## Целевая структура UI

```text
Профиль
├── Личные данные
├── Профессиональные данные
├── Рабочие данные
├── [Сохранить]
└── [Назад]
```

- Три группы должны быть реализованы как аккордеон внутри единого экрана Профиля, а не как три отдельные папки/ветки навигации.
- Каждая секция аккордеона раскрывается и сворачивается повторным нажатием.
- Уже существующие UI-поля внутри секций сохраняются: текстовые поля, списки, выборы, описания и другие существующие элементы.
- Внутри отдельных секций не создаются собственные `Назад`/`Сохранить`.
- `Сохранить` относится ко всему Профилю и является общим UI Action.
- `Назад` относится ко всему экрану Профиля и возвращает на один шаг назад, в Настройки.

# Общие правила UI / Modal

## Modal

Modal — один общий UI-механизм CoBook.

- Не создаётся отдельный Modal для Процедур, Товаров, выбора времени, перерыва и других сценариев.
- Один общий Modal используется с разным содержимым.
- Общий CSS.
- Общее позиционирование.
- Всегда привязка к центру экрана.
- Любое устойчивое смещение Modal вниз/вверх/влево/вправо считается ошибкой общего UI/CSS.
- `×` — общий UI Action закрытия.
- `Сохранить` — общий UI Action сохранения данных сценария.
- В Modal нет кнопки `Назад`: навигационное `Назад` предназначено для перехода между экранами/ветками, а не для закрытия Modal.
- Внутри Modal могут использоваться дополнительные UI-компоненты: выпадающие списки, переключатели, барабаны выбора времени, дополнительные поля и другие вложенные UI.
- Дополнительный UI внутри Modal не превращает Modal в отдельный/локальный компонент.

## Общий UI и CSS

- UI-компонент остаётся общим независимо от того, в какой ветке и с какими данными он используется.
- Разные данные или дополнительные вложенные UI не являются основанием для создания отдельной UI-функции.
- Общий CSS является единым визуальным слоем.
- Локальные CSS/renderer допустимы только как контекстное использование общего визуального слоя, а не как отдельная визуальная система.
