# 1. ТЕКУЩАЯ СТРУКТУРА ЭКРАНА ГРАФИКА

Экран Графика состоит из трёх блоков:

```text
График
├── Заголовок
├── Календарь
└── Временной блок
```

На этом этапе разбирается только то, что фактически существует и было обнаружено/обсуждено. Будущие элементы не добавляются.

---

# 2. ЗАГОЛОВОК

## UI

В заголовке Графика должен существовать **счётчик / показатель выбранного месяца**.

Пример:

```text
Май 2025                 3 рабочих дня · 48 часов
```

Точная будущая позиция счётчика пока не фиксируется как окончательная. Сейчас фиксируется сам факт его принадлежности к блоку Заголовка.

### Разделение ответственности

```text
График
└── рассчитывает показатель выбранного месяца

Общий UI
└── отображает компонент Counter

CSS
└── определяет его визуальный вид и размещение в конкретном контейнере
```

Смысл показателя и его значения принадлежат Графику. Само понятие UI-компонента `Counter` должно быть общим.

## Общий Counter

`Counter` — общий UI-компонент, а не отдельный `HeaderCounter` или `FolderCounter`.

Один и тот же компонент может иметь разные экземпляры:

```text
Counter → Header Графика
Counter → папка Клиентов
Counter → другой контекст
```

Изменение размещения одного экземпляра не должно менять размещение другого экземпляра.

Это достигается тем, что общий компонент не содержит жёстко зашитое позиционирование под конкретный экран.

# 3. КАЛЕНДАРЬ

## Общая структура

Календарь использует общий `Calendar Grid`.

```text
UI Core
└── Calendar Grid
    ├── используется Графиком
    └── используется Журналом
```

`Calendar Grid` не принадлежит Графику и не принадлежит Журналу.

## Переключение периода

### Текущее состояние

🔴 Сейчас год и месяц представлены двумя отдельными переключателями.

### Целевое состояние

📌 Один общий переключатель периода:

```text
2025 · Май
↓
2025 · Июнь
↓
2025 · Июль
↓
2026 · Январь
```

Год и месяц являются одним состоянием выбранного периода и должны визуально переключаться единым механизмом.

Это правило относится к общему UI, потому что такой же переключатель используется/должен использоваться в других календарях, например в Журнале.

# 4. CALENDAR GRID — СЕТКА

## Соседние месяцы

### Текущее состояние

🔴 В сетке видны даты предыдущего месяца, но полный хвост дат следующего месяца не отображается.

### Целевое состояние

📌 Сетка рассчитывается динамически и показывает даты соседних месяцев, необходимые для заполнения календарной области.

Например, если конец выбранного месяца приходится на понедельник, в сетке должны быть видны даты следующего месяца до конца календарной строки.

## Размер и назначение ячейки

### Текущее состояние

🔴 Ячейка визуально слишком похожа на маленькую кнопку.

### Целевое состояние

📌 Это полноценная календарная ячейка, внутри которой может размещаться дополнительная информация.

В Графике внутри неё, например, может отображаться `8:30`.

Сама сетка при этом остаётся общей для календарей.

# 5. CALENDAR GRID — ОБЩИЕ ПРАВИЛА ОТОБРАЖЕНИЯ

Общий UI знает правила отображения календарных дат.

```text
Дата предыдущего / следующего месяца
→ светло-серый цвет + меньший шрифт

Дата текущего выбранного месяца
→ стандартный вид

Суббота / воскресенье
→ красное отображение

Рабочий день
→ жирный шрифт

Выходной день
→ обычный шрифт
```

Важно:

**Выходной день здесь означает статус рабочего графика, а не субботу/воскресенье.**

Состояние «рабочий / выходной» не является кнопкой и не является действием.

Это визуальное состояние календарной сетки.

# 6. ВЫБОР ДАТЫ — ОТДЕЛЬНЫЙ UI

`Date Select` / выбор даты — отдельный UI-компонент.

Он не должен смешиваться с постоянным отображением статуса даты.

## Визуал выбора

```text
Выбор рабочих дат
→ бежевый фон + чёрный текст

Выбор выходных дат
→ коричневый фон + белый текст
```

Это **заливка выбранной даты для текущей операции**, а не постоянный визуал рабочего/выходного дня.

## Групповой режим выбора

После первой выбранной даты определяется направление операции:

```text
Первая дата — нерабочая
→ дальше можно выбирать только нерабочие даты
→ рабочие даты нельзя добавить в эту группу

Первая дата — рабочая
→ дальше можно выбирать только рабочие даты
→ нерабочие даты нельзя добавить в эту группу
```

Нельзя смешивать два противоположных состояния в одной операции.

Это правило относится к функционалу выбора Графика, а визуальный механизм выбранной ячейки относится к UI-компоненту Date Select.

# 7. REVERSE ACTION BUTTON

Эта кнопка была разобрана ранее и повторно здесь не разбирается.

Это **общий UI-компонент** с двумя состояниями:

```text
Применить рабочий день
↕
Применить выходной день
```

Механизм реверса, базовый визуал, цвета состояний и общая логика компонента должны быть едиными во всех местах приложения.

Конкретный текст и действие передаются контекстом Графика.

Владение `WorkingDay` при этом остаётся у Графика.

# 8. ВЛАДЕНИЕ РАБОЧИМ ДНЁМ

Сущность `WorkingDay` принадлежит Графику.

```text
Core
 ↓ запрос / передача действия
График
 ↓ владеет
WorkingDay
```

Рабочий день формируется из:

```text
Дата + Временной диапазон
        ↓
    WorkingDay
```

### Запрещённая архитектура

```text
❌ Main управляет WorkingDay
❌ Journal управляет WorkingDay напрямую
❌ Core напрямую создаёт WorkingDay
❌ Journal создаёт собственную копию WorkingDay
```

### Правильная модель Журнала

Журнал может запросить у Графика:

```text
создать рабочий день
изменить рабочее время
убрать рабочее время
```

Но Журнал не становится владельцем сущности.

Если Журнал показывает данные рабочего дня, он получает их от Графика.

# 9. ВРЕМЕННОЙ БЛОК

Временной блок является частью Графика, потому что временной диапазон является частью `WorkingDay`.

```text
График
└── WorkingDay
    ├── Дата
    └── Временной диапазон
        ├── С
        └── До
```

Визуально временной блок сейчас воспринимается корректно.

Полная проверка работоспособности его действий выполняется отдельным этапом.

---

# 10. TIME PICKER — ВЫБОР ВРЕМЕНИ

`Time Picker` — общий UI-компонент.

При нажатии на поле времени открывается единое окно выбора времени с барабаном, аналогичным iPhone.

Один и тот же компонент используется для двух полей:

```text
С  → Time Picker
До → Time Picker
```

Это не два разных UI-компонента.

Различается только контекст вызова и поле, в которое возвращается результат.

---

# 11. РАСЧЁТ РАБОЧЕГО ВРЕМЕНИ

Выбор времени:

```text
10:00 → 18:00
```

даёт результат:

```text
8:00
```

Выбор:

```text
10:00 → 18:30
```

даёт:

```text
8:30
```

Сам расчёт относится к Графику.

```text
Time Picker UI
→ позволяет выбрать время

График
→ получает From / To
→ рассчитывает длительность
→ хранит/использует результат

Calendar Grid UI
→ отображает результат
```

UI не должен становиться владельцем расчёта рабочих часов.

---

# 12. ОТОБРАЖЕНИЕ 8:30

`8:30` — специфическое правило отображения Графика.

### Правила

- отображается только в Графике;
- формат строго `часы:минуты`, например `8:30`;
- без «ч»;
- без «мин»;
- отображается только внутри ячеек дат фактического выбранного месяца;
- в датах предыдущего и следующего месяца, попавших в сетку, `8:30` не отображается.

### Разделение

```text
График
→ решает, что для его рабочего дня нужно показать длительность

Общий Calendar Grid
→ знает, как отобразить содержимое ячейки

CSS
→ определяет внешний вид текста
```

Владение данными не переносится в UI из-за того, что UI их отображает.

---

# 13. СЧЁТЧИК В ЗАГОЛОВКЕ ГРАФИКА

График должен агрегировать показатели выбранного месяца.

Пример:

```text
Май 2025
3 рабочих дня
48 часов
```

Само значение принадлежит Графику как вычисляемый показатель.

`Counter` является общим UI-компонентом отображения.

Один общий компонент может иметь разные экземпляры и разные контейнеры:

```text
Counter → Header Графика
Counter → папка Клиентов
```

Изменение позиции одного экземпляра не должно менять позицию другого.

# 14. ГРАНИЦА ОТВЕТСТВЕННОСТИ UI / ГРАФИКА

```text
График
├── владеет WorkingDay
├── хранит/использует временной диапазон
├── рассчитывает длительность рабочего времени
├── рассчитывает агрегированный показатель месяца
└── определяет, какие данные специфичны для Графика

UI Core
├── предоставляет Calendar Grid
├── предоставляет Date Select
├── предоставляет Reverse Action Button
├── предоставляет Time Picker
└── предоставляет Counter

CSS
└── определяет визуальный вид и размещение конкретных UI-экземпляров
```

UI не становится владельцем сущности только потому, что отображает её состояние.
