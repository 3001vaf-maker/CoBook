## Правило рабочих веток

Рабочие изменения выполняются только в отдельной ветке от `main`.

Текущий следующий этап: отдельная ветка для **M12. Календарь**.

Во время разработки `main` не изменяется.

После завершения разработки рабочая ветка сопоставляется с `main`. Только после проверки и явного утверждения пользователя изменения переносятся в `main`, а соответствующий пункт в этом файле получает статус 🟢.

## Правила ответа и проверки

1. При каждом изменении интерфейса ChatGPT обязан предоставлять пользователю рабочее HTML-приложение для визуальной проверки результата. Пользователь должен видеть приложение, а не исходный код.
2. В ответе всегда указывать полный SHA коммита, содержащего проверяемое изменение, чтобы пользователь мог зафиксировать его у себя.
3. В конце каждого ответа по выполненному изменению обязательно указывать в отдельном блоке: **Коммит:** полный SHA; **Приложение:** ссылка на рабочую публикацию приложения.
4. Запрещено присылать пользователю код приложения, если пользователь прямо не попросил код.
5. Запрещено отвечать вместо результата цитатой/ссылкой на исходный код или точку репозитория, когда пользователь просит приложение для проверки.
6. Запрещено создавать новые ветки без явной команды пользователя. Команда считается подтверждённой только если пользователь трижды явно написал «создать ветку».
7. Исключение к правилу создания веток: если ChatGPT задаёт пользователю вопрос «что делаем дальше?», последующая явная команда пользователя о создании ветки считается достаточным основанием для создания ветки.
8. `main` не изменять во время разработки рабочих изменений.
9. Перед ответом с рабочей ссылкой проверить, что публикация действительно открывает приложение, а не исходный HTML-код, 404 или пустой экран.
