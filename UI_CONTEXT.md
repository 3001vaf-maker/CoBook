# CoBook — UI CONTEXT MAP

Этот файл фиксирует адресацию интерфейсов. Пользователь не обязан знать технические имена.

## Правило адресации

Задача сначала определяется по разделу, затем по полю внутри раздела.

| Пользовательское название | Технический адрес | Назначение |
|---|---|---|
| График → календарь | `SCHEDULE → CALENDAR` | Календарь формирования рабочего графика |
| Журнал → месяц-календарь | `JOURNAL → MONTH_CALENDAR` | Месячный календарь журнала |
| Всплывающий календарь | `MODAL → DATE_PICKER` | Календарь внутри модального окна |

## Правило контекста

1. Если пользователь назвал раздел и поле, работать только внутри указанного адреса.
2. Если пользователь после переключения раздела говорит только «календарь», использовать календарь текущего активного контекста.
3. Никогда не менять другой календарь только потому, что он использует похожие CSS-классы или функции.
4. Перед изменением календарной логики проверить конкретный технический адрес и его DOM-область.
5. Общие имена вроде `calendar`, `month-day`, `calendar-grid` не считать достаточным основанием для выбора интерфейса.

## Техническая карта

```text
SCHEDULE (График)
└── CALENDAR
    ├── CALENDAR_HEADER
    ├── CALENDAR_GRID
    ├── WORK_DATE_SELECTION
    └── WORK_INTERVAL

JOURNAL (Журнал)
├── DAY_VIEW
└── MONTH_CALENDAR

MODAL
└── DATE_PICKER
```

## Правило очистки

Перед удалением, переносом или заменой любого календарного файла/модуля обязательно проверить все подключения, вызовы, DOM-селекторы и зависимости по всему проекту. Не удалять файл только потому, что его имя выглядит устаревшим.

Перед коммитом проверять, что изменение затронуло только заявленный технический адрес и не изменило соседние интерфейсы.
