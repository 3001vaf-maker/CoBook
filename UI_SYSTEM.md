# CoBook UI System

## Purpose
Единая визуальная система CoBook. Эталон интерфейса — раздел `Настройки`. Все экраны используют одну общую UI-систему и не создают локальные варианты существующих кнопок, переключателей или цветов.

## Single CSS source
Единый источник семантического UI — корневой `styles.css`. Модульные CSS-файлы могут содержать только уникальную геометрию/раскладку конкретного экрана и не имеют права переопределять внешний вид общих UI-компонентов.

## Semantic UI variants
- `back` — возврат на предыдущий уровень/экран.
- `action` — основное подтверждающее действие: сохранить, создать, подтвердить.
- `folder` — переход в раздел/подраздел.
- `tab` — переключение между соседними представлениями одного раздела. В текущей реализации общий класс переключателя — `service-tab`; это не Action.
- `select` — открытие выбора значения.
- `secondary` — вторичное действие.
- `danger` — удаление или другое потенциально разрушительное действие.

## Design tokens
Базовые значения находятся в `:root` файла `styles.css` и используются через CSS custom properties:
- `--ui-back`
- `--ui-folder`
- `--ui-action`
- `--ui-tab-active`
- `--ui-select`
- `--ui-secondary`
- `--ui-danger`
- `--ui-radius`
- `--ui-folder-radius`
- `--ui-gap`
- `--ui-control-h`

Новые значения цвета для существующей семантики не добавлять в модульные CSS. Если появляется новый тип UI-элемента, он добавляется в единую систему `styles.css`, а не создаётся как локальный вариант модуля.

## Semantic distinction
`Action` и `Tab` — разные сущности:
- `Action` выполняет действие: `Создать`, `Сохранить`, `Подтвердить`.
- `Tab` переключает представление: `Товары / Процедуры`, `Материалы / Рецепты`.

Нельзя стилизовать `Tab` как `Action` только потому, что он является кликабельным.

## Layout rules
- `Back` является навигационной кнопкой и не меняет положение произвольно от модуля к модулю.
- `Action` визуально отделяется от `Back` и использует единый `--ui-action`.
- `Folder` используется одинаково для однотипных переходов независимо от названия раздела.
- `Tab` использует единый силуэт и единое состояние active во всех разделах.
- `Select` выглядит как единый элемент выбора во всех формах.
- Между самостоятельными действиями используется единый `--ui-gap`.

## Naming rules
Разные предметные сущности не используют одно и то же семантическое имя:
- `Рабочие материалы` = то, с чем мастер работает.
- `Работа` / `Рабочее место` = то, где мастер работает.

Внутренние идентификаторы этих сущностей должны различаться, чтобы изменение одного модуля не затрагивало другой.

## Rule for future changes
Перед созданием нового класса UI сначала проверить, существует ли подходящий semantic variant. Если существует — использовать его. CSS override для исправления архитектурного расхождения не является допустимым решением.

Если меняется общий стиль `Action`, `Back`, `Tab`, `Folder`, `Select` или другой семантической сущности, изменение должно выполняться в единственном источнике `styles.css` и распространяться на все места использования автоматически.
